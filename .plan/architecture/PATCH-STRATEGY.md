# a1 patch strategy discovery

Recorded 2026-09-17; engineering implementation choice under the existing build/distribution contract. Patch production and reconstruction remain a8 work.

The pinned candidate RetroMCP resource archive contains Tiny v2 mappings with `named`, `client` and `server` namespaces. Examples: World maps to `fd` client / `dj` server; Entity to `sn` / `lq`; ItemStack to `iz` / `fy`; Packet to `ki` / `gt`. The same shared class therefore cannot retain both original names in one compiled output. Method/field names also differ by side, and the merge has intentionally reconciled aliases and united APIs. Historical exact decompiler/mapping provenance is still unknown; these mappings are evidence, not proof that every untouched recompiled class matches its original.

Keep named Origins classes for both direct builds and the future patch. Do not attempt to retain a mixture of original obfuscated game classes and named replacements. The a8 patch must explicitly remove original game class entries and install the complete named game implementation, including new shared classes and the documented entry point. Compare resources by path/content: replace changed resources, add new ones, retain only explicitly verified unchanged entries and record deletions. Remove obsolete manifest/signature metadata according to the reconstruction contract. Third-party bundled classes require explicit ownership/dependency classification before deletion; a filename-only guess is insufficient.

This is a full implementation replacement strategy, not a small changed-method overlay. Mapping tables remain useful for provenance/debugging, but reobfuscation is not a required build step. Preserve the exact original jar SHA-256, complete added/replaced/deleted entry lists, compiler/runtime requirements and external dependency/native configuration. At a8, applying the patch to that exact original must reconstruct the direct build's effective content and launch successfully in a clean installation. No patch artifact, reconstruction PASS or redistributable package is claimed in a1.

Evidence: [mapping namespaces, examples, hashes and current artifact hashes](../status/evidence/2026-09-17-a1-unified/inputs.json). Original references were read only. This follows [BUILD-DISTRIBUTION](../BUILD-DISTRIBUTION.md), which permits a remapped complete replacement set when original-name preservation is impractical.
